# AI Underlay 产品化审查与改造

日期：2026-10-17。审查基线：`db27b5e`，实现分支：`codex/product-settings-polish`。

## 产品判断

当前产品的核心价值已经清楚：在菜单栏背景显示真实额度和活动状态，同时保留一个紧凑的额度弹窗。主要问题是配置界面仍按开发模块组织，暴露了渲染参数、样例键和未完成的安装方案。用户很难判断应该先做什么、操作是否完成、当前看到的是否为真实数据。

这次采用原生 macOS 设置组织与针对性状态修复。相比只改文案，它能修复真实的操作问题；相比重写额度与渲染架构，它保留已验证的产品能力，修改范围与风险更可控。

## 问题、影响和修改方案

| 优先级 | 基线问题与代码位置 | 用户影响 | 修改方案 |
|---|---|---|---|
| P0 | `AIUnderlayApp` 的 Settings scene 为 EmptyView | 系统菜单或快捷键可能打开空白窗口 | 系统设置命令统一调用 SettingsOpener |
| P0 | 再次打开应用时只切换依赖图标位置的弹窗 | 隐藏菜单栏图标后缺少可靠恢复入口 | 再次打开应用显示正式设置窗口 |
| P0 | `AgentTab` 安装和卸载使用 try?，随后显示成功 | Hook 安装失败却被认为已接入 | 保留预览再应用，do/catch 报告实际结果 |
| P0 | `SettingsStore.save()` 静默吞错，读取损坏文件后直接回退默认 | 重启丢配置且无提示，后续写入可能覆盖损坏原件 | 显示持久化错误与重试，损坏原件替换前备份 |
| P1 | `startEngine()` 重启数据源前不停止原调度器 | 旧请求可能在代理或连接改变后回写 | 停止旧调度，代次隔离异步结果，暴露刷新状态 |
| P1 | 请求失败后读取最近缓存可能仍为 valid | 缓存被误读为当前有效额度 | 失败回退强制标为 stale，并保留真实额度数值 |
| P1 | 六个标签等权、固定窗口，外观页混合日常与调试参数 | 找设置费力，长说明挤占界面 | 可调整窗口、侧栏任务分组、标题与简短说明 |
| P1 | 无效布局/动效选项仍可调，依赖条件难理解 | 用户调整后看不到效果 | 明确禁用条件、解释原因并保留已保存偏好 |
| P1 | 预览使用原始 fixture key，实时与样例提示不充分 | 样例额度容易被误认为真实额度 | 友好样例名称、持续预览标识、一键回实时 |
| P1 | `ThemeTab` 控件部分回退到内置值，而渲染取主题有效值 | 控件色板、滑块与菜单栏可能不一致 | 使用实际解析链：个人覆盖 > 主题 > 内置 |
| P1 | 切主题仍受个人覆盖，但界面不提示 | 误以为主题切换失效 | 标出自定义覆盖，提供按类别跟随主题与整体恢复 |
| P1 | Providers 将 stale 和 valid 都表述为已登录 | 混淆授权、获取结果和数据新鲜度 | 分开显示应用开关、上游开关、额度可用性与错误 |
| P1 | 连接测试先触发请求再立即读取旧快照 | 结果反馈不可信 | 跟随实际刷新生命周期更新，不提前宣布成功 |
| P2 | Engine 显示需要开发者填写 URL/SHA 的托管安装说明 | 用户遇到无法执行的产品入口 | 隐藏未完成流程，提供已支持的检测与外部安装指引 |
| P2 | 材质参数、主题文件工具、动效微调占据主流程 | 默认设置复杂，后续选项容易继续堆积 | 高级项折叠，常用项优先，恢复动作限定范围 |
| P2 | 弹窗无服务商时空白、无数据时缺少下一步 | 用户无法判断是没启用、没连接还是额度耗尽 | 可操作空状态、连接提示、缓存/预览/暂停标识 |

## 设置与选项维护原则

- 设置状态继续由 SettingsStore 统一持久化，UI 不另建第二套配置或改变 JSON 键语义。
- 额度、玻璃主题色、状态灯三个颜色角色独立；恢复动作明确范围，主题不能改变数据或告警优先级。
- 高频显示取数据源实际结果；成功、失败、进行中和样例状态使用不同反馈，不用“已点击”冒充成功。
- 高级参数保留能力但渐进展开。新增选项必须说明适用条件、有效默认值、恢复范围和持久化行为。
- 变更集中于任务相关代码；现有双侧拆分、真实额度、点击穿透与 Reduce Motion 属于回归边界。

## 可执行交付顺序

1. 整理设置结构、窗口和布局依赖；让普通用户能理解配置。
2. 修复主题有效值和覆盖反馈；保留自定义能力。
3. 修复连接、代理与 Hook 配置的错误和加载反馈。
4. 集成持久化、刷新生命周期和弹窗状态；审查跨页一致性。
5. 完整测试、Debug 构建与原生窗口检查后，提供本地预览和验收报告。

实施分工：三个子任务均指定 `group/auto-deepseek-v4-1-flash`，推理等级 `max`；主任务负责集成与最终验证。子任务明细见同目录的布局、主题和连接说明。

## 本轮验收与限制

最终结果记录在 `validation.md`。自动测试、离线截图与原生窗口操作分别说明，不能替代外接显示器、不同刘海硬件和长时间运行的人体验收。

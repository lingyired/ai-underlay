# Codex 无 Hook 活动检测

## 已确定方案

用户要求参考 Codex Pacer，减少安装/信任 Hook 的负担。沿用当前
`codex/product-settings-polish` 工作区，不提交或发布。

1. 采用原生 Swift Codex Desktop IPC 采集。复用本机 Codex Pacer 已实现的有界
   JSON 解析、版本化快照/原子补丁、只读订阅和连接生命周期，并保留 MIT 归属。
2. 本次只启用本机 Codex。现有 SQLite/rollout 日志持续兜底，额度仍来自
   CodexBar。实时状态逐会话优先，不用全局“已连接”掩盖未覆盖会话。
3. Codex 的 Hook 不再参与状态判定，不再推荐安装或要求用户信任。已有应用自有
   Hook 只提供手动清理入口，不自动修改用户 Agent 配置。Claude 保留原流程。
4. 断线、版本/补丁不兼容时停止使用失效运行证据、回退日志并说明能力受限；
   已观察到的待处理请求不能因为断线直接伪装成已解决。
5. 只保留会话 ID、状态、请求种类和时间；不记录对话正文、问题、答案、命令、
   额度账号或原始 IPC 帧。重连有间隔，订阅和帧大小有上限，不增加高频扫描。

## 选择理由

只隐藏 Hook 设置不能解决细分状态缺失；只增强日志解析无法覆盖即时待答请求。
采用 Pacer 原生 IPC 适配器比重新实现私有协议更可核验，同时通过可替换适配层
与日志兜底控制桌面端协议升级的风险。不引入 Python 运行依赖或整个 Pacer 产品。

## 分工与验收

- 主任务：实时帧到本项目 AgentSession 的状态适配、优先级与回退、coordinator
  集成、归属说明、回归测试、构建和实机只读验证。
- 子任务：限定范围移植原生 IPC 适配器及协议回归；另一子任务调整 Agent 设置
  和旧 Codex Hook 清理入口。沿用用户指定模型与 max 推理等级。
- 验证启动/运行/终止、异步提问与回复、批准请求、断线/重连、未知协议、原子
  补丁回退、已有 Hook 不影响 Codex 状态；完整测试、Domain purity、Debug 构建。
- 实机验证单独标明实际观察与合成协议测试，不调用真实工具请求制造审批，也不
  自动安装/移除 Hook。保留已有外观、主题、双侧配色和真实额度行为。
